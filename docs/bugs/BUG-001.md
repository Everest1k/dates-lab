# BUG-001. 2000 год не считается високосным

| Поле | Значение |
|------|----------|
| Модуль / функция | `datediff.IsLeapYear` |
| Статус | Открыта (Open) |
| Категория | Серьёзная (Major) |
| Тестовый случай | `TestIsLeapYear/делится_на_400` |
| Обнаружил | <Маркевич Никита Серегеевич>, 09.10.2026 |
| Исполнитель | <Романенко Кирилл Юрьевич> |

## Шаги воспроизведения
1. Клонировать репозиторий, перейти в корень проекта.
2. Выполнить: `go test -run 'TestIsLeapYear' -v ./datediff`
3. Тест вызывает `IsLeapYear(2000)`.

**Полученный результат:** `false`
**Ожидаемый результат:** `true` (год делится на 400, см. SPEC_datediff.md, общие правила)

## Дополнительно
Вывод теста:

```
datediff_test.go:28: IsLeapYear(2000) = false, ожидалось true
--- FAIL: TestIsLeapYear/делится_на_400
```

Годы 2024, 2023 и 1900 определяются верно. Предположительно, не реализована
часть правила «либо делится на 400». Ошибка затрагивает и другие функции:
`DaysInMonth(2000, 2)` вернёт 28, `IsValid` отвергнет 29 февраля 2000 года,
`DaysBetween` ошибается на 1 день, если одна из дат приходится на март–декабрь
2000 года: `DaysBetween({2000 1 1}, {2000 3 1})` = 59 вместо 60.
